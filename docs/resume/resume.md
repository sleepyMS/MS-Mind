# 자기소개서

## 1. 자신만의 특별함 (성장과정, 학교생활/경력내용, 가치관)

'Deep Dive & Wide View'가 저의 성장 철학입니다. 하나의 기술을 깊이 파고드는 동시에 전체 시스템을 조망하는 균형을 추구합니다.
강남대학교 소프트웨어응용학부에서 4학기 연속 학부 수석(GPA 4.24/4.5)을 유지하며 이론적 기반을 다졌습니다. 동시에 교내 AI 챗봇 서비스 'KangNaengBot' 프론트엔드를 개발하며 실무 역량을 쌓았습니다.
저는 기술이 사용자의 문제를 해결할 때 비로소 가치가 있다고 믿습니다. 그래서 단순히 코드를 작성하는 것을 넘어, 사용자가 가장 직관적으로 목적을 달성할 수 있도록 돕는 '공간 경험 설계자'를 지향합니다.

---

## 2. 자신의 강점과 단점

### [강점: 빠른 학습력과 문제 해결 능력]

새로운 기술을 빠르게 습득하여 실무에 적용하는 것이 강점입니다. 이를 강화하기 위해 기술 블로그를 운영하며 학습 내용을 문서화하고 있습니다. 'KangNaengBot' 프로젝트에서 처음 접한 RAG 시스템과 Optimistic UI 패턴을 3일 만에 학습하여 체감 지연 시간 0ms의 서비스를 구현한 경험이 있습니다.

### [단점: 완벽주의로 인한 일정 지연]

초기에는 완벽한 코드를 추구하느라 일정을 지연시킨 적이 있습니다. 이를 극복하기 위해 'API-First 개발 방식'을 도입했습니다. MVP를 빠르게 출시한 후 사용자 피드백을 반영하여 개선하는 방식으로 전환하였고, 하루 만에 핵심 기능을 완성하는 속도와 품질의 균형을 찾았습니다.

---

## 3. 차별화된 방식으로 성공적인 결과를 얻은 경험

- **[기존 방식]** 대학생들은 매 학기 수강신청 전 수십 개의 과목 시간표 조합을 수작업으로 비교해야 했습니다. 기존 시간표 앱들은 단순 CRUD 기반으로 사용자가 직접 모든 조합을 입력해야 했습니다.
- **[차별화된 시도]** 자연어로 원하는 과목을 말하면 AI가 충돌 없는 최적의 시간표 조합을 자동 생성하는 RAG 기반 시스템을 제안했습니다.
- **[진행과정]** API 명세서를 먼저 작성하는 'API-First' 방식으로 프론트엔드와 백엔드 병렬 개발을 진행했습니다. Mock 데이터로 UI/UX를 선검증한 후 실제 API를 연동했습니다.
- **[결과]** 하루 만에 MVP를 완성했고, 클라이언트 사이드 필터링으로 API 재호출 없이 0ms 반응성을 달성했습니다. 사용자들은 수작업 대비 90% 이상의 시간을 절약할 수 있게 되었습니다.

---

## 4. 가장 어려웠던 경험과 극복, 배운점

- **[어려웠던 경험]** 'KangNaengBot' 프로젝트에서 LLM의 필연적인 응답 지연(1~5초)이 가장 큰 난관이었습니다. 사용자들은 메시지 전송 후 "멈췄나?"라고 느꼈고, 이는 서비스 이탈의 주요 원인이었습니다.
- **[극복 노력]** 서버 성능을 높이는 것은 한계가 있었기에, '체감 성능'을 높이는 방향으로 전환했습니다. Optimistic UI 패턴을 도입하여 API 응답 전에 UI를 선반영하고, 실패 시에만 롤백하는 방식을 구현했습니다. 추가로 Hover Prefetching과 SWR 패턴을 적용하여 세션 전환 시에도 즉각 반응하도록 했습니다.
- **[배운점]** 물리적 성능 개선보다 '사용자가 느끼는 속도'가 더 중요하다는 것을 배웠습니다. UX 엔지니어링이 기술적 한계를 극복하는 핵심 무기임을 체감했습니다.

---

## 5. 지원 직무 차별화 역량과 노력

### [차별화 역량: AI를 사용자 친화적 인터페이스로 연결하는 UX 엔지니어링]

LLM의 기술적 복잡성을 사용자가 전혀 인지하지 못하게 감추는 프론트엔드 개발이 저의 차별화 역량입니다.

### [갖추기 위한 노력]

1. RAG 기반 AI 챗봇 'KangNaengBot' 프론트엔드를 직접 개발하며 LLM 서비스의 UX 문제와 해결책을 체득했습니다.
2. Optimistic UI, SWR 패턴, 자동 재시도 로직 등 체감 속도 개선 기법을 연구하고 실무에 적용했습니다.
3. React, TypeScript, Next.js 등 모던 프론트엔드 기술과 Python, FastAPI를 활용한 백엔드 개발 역량을 갖춰 풀스택으로 서비스를 구현할 수 있습니다.
4. 기술 블로그를 통해 학습 내용을 정리하고 공유하며 지속적인 성장을 추구합니다.

## 6. 해커스 입사 이유와 공헌

### [입사 이유]

해커스가 LLM 기반 교육 서비스와 AI 튜터링 시스템 개발에 투자하고 있다는 점에 큰 매력을 느꼈습니다. 저는 이미 교육 도메인(대학교 시간표 생성)에서 AI 챗봇을 개발한 경험이 있고, RAG 시스템과 LLM 응답 최적화에 대한 실무 지식을 보유하고 있습니다. 이 역량을 해커스의 EdTech 서비스에 즉시 적용할 수 있습니다.

### [공헌 계획]

1. LLM 응답 지연을 사용자가 인지하지 못하게 하는 UX 최적화 기법을 해커스 서비스에 적용하겠습니다.
2. API-First 개발 방식으로 프론트엔드-백엔드 병렬 작업 효율을 높여 빠른 MVP 출시에 기여하겠습니다.
3. 사용자 관점에서 AI 튜터링 시스템의 UX를 지속적으로 개선하여 학습자 만족도 향상에 공헌하겠습니다.

## 7. 자유양식

**질문: AI First 개발 철학과 활용 역량**

**답변:**
개발 전 과정에서 AI를 적극 활용합니다. Google Antigravity와 MCP 도구(Context7, Sequential Thinking, TestSprite)를 연동하여 문서 검색-분석-테스트 자동화 워크플로우를 구축했습니다. 21st.dev 같은 AI 디자인 스튜디오로 UI를 신속하게 프로토타이핑한 후 코드로 구현하는 프로세스를 확립했습니다.
단순히 AI를 개발 도구로 활용하는 것을 넘어, Cortex 프로젝트에서는 사용자가 직접 AI 모델을 학습하고 배포하는 No-Code 인터페이스를 설계했습니다. AI의 '사용자'이자 AI 서비스의 '구현자'로서 양면의 경험을 갖추고 있습니다.
이러한 AI First 마인드셋을 바탕으로, 해커스의 LLM 기반 교육 서비스 개발과 업무 자동화에 즉시 기여할 수 있습니다.
